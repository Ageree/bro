# Большие цели: `.harness/goals/`

Журнал долгих работ, которые не помещаются в одну сессию. Один каталог на цель,
имя — слаг (`bro-2-0`, `browser-3-0`, `watchers-2-0`, `silent-agent-rca`).

## Файлы

| Файл | Зачем |
| --- | --- |
| `goal.md` | Что строим и почему. Пишется один раз, правится редко. |
| `events.jsonl` | Хроника: `{ts, turn, event, note}`, по строке на событие. Только дописывать. |
| `state.json` | `{goal_id, status, turn, started_at, last_turn_at, finished_at}`. Есть не у каждой цели. |
| `continuation.md` | С чего начать следующий ход, если предыдущий оборвался. |
| `briefs/` | Задания для субагентов, по файлу на кусок работы. |
| `acceptance.md`, `audit-*.md` | Критерии приёмки и вердикты аудита. |

## Как пользоваться

- Сессия начинается — `session-start` хук уже показал три последние цели и их
  последнее событие. Если работа продолжает одну из них, читай `goal.md` и
  `continuation.md` целиком, прежде чем трогать код.
- Ход закончился — допиши строку в `events.jsonl` и обнови `continuation.md`,
  чтобы следующая сессия не начинала с нуля. Если у цели есть `state.json`,
  поправь `status`/`last_turn_at` там же.
- Цель закрыта — `status: "done"` и `finished_at`. После этого хук перестаёт
  подсвечивать её как активную.
- Выводы, которые переживут саму цель, не оставляй в `events.jsonl`: их место в
  `MEMORY.md`. `.harness` — хроника одной работы, `MEMORY.md` — то, что знает
  проект вообще.
