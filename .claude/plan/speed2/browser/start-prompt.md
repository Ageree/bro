# Единица «browser»: браузерное поручение — время до результата (только чтение)

Ветка: `claude/speed2-browser` от `origin/bro-next`. Бюджет: 400 ₽: каждый запуск
браузера платный, перед каждой серией смотри баланс RouterAI.
Сначала прочитай `PROTOCOL.md`:
`git show origin/claude/speed2-plan:.claude/plan/speed2/PROTOCOL.md`.

## Задача — только эта

Измерить, сколько человек ждёт результат типичного поручения браузеру на чтение, и
сократить это время.

## Что известно (`docs/browser-speed.md`, `docs/browser-pool.md`, dev-notes «Браузерные поручения»)

- Пул на выделенном сервере Selectel `bro-dedicated-3`, Firecracker. Chrome до CDP
  0,2–0,8 с, распаковка профиля 0,35 с. Узкое место — LLM шага browser-use и число
  шагов.
- Пилоты сейчас только у владельца:
  - `FLASH_SEARCH_WORKSPACES` — flash mode для старта поиска без согласия и оплаты;
  - `BROWSER_FAST_WORKSPACES` — Together без `requireParameters`, `llmTimeoutSeconds`
    25, flash для поиска.
  Оба с 04–05.10. Цифр «пилот против без пилота» на одних задачах нет. Если пилоты
  окупаются, их можно включить всем; включает координатор, по правилу владельца.
- heads-up «сейчас посмотрю» приходит за ~3 с. Дальше идут выбор выхода прокси
  (`turnExitBudgetMs`; первый российский выход берётся всегда), песочница
  (прогрев при сообщении), запуск worker и отчёт (ход-отчёт `browser-report`).
- Журнал: строки `[browser-vm]` и `[browser-use]` eve; трасса шагов запуска
  (`trail/<id>/steps.jsonl`, см. dev-notes); `ops/browser-runs.sh`.

## Что сделать

1. 5–8 типичных поручений на чтение, без входа на сайты:
   - цена товара на Ozon, WB или Яндекс Маркете;
   - сеансы в кино на сегодня;
   - наличие товара в магазине;
   - часы работы и меню ресторана с сайта.
   Каждое 2–3 раза.
2. Разложи время по этапам: сообщение → heads-up → старт запуска (очередь, выход,
   песочница) → шаги worker (число, LLM на шаг, действие на шаг) → отчёт доставлен.
   Где возможно, сравни с пилотами и без них. Пилоты у владельца уже есть; «без
   пилота» — синтетика или стенд worker (`browser-vm/worker`, есть тесты на настоящем
   Chromium).
3. Ускорь главное:
   - на стороне Бро: подготовка, очередь, выход, текст поручения, отчёт;
   - на стороне worker: если правка нужна, сделай её и опиши выкат. Новый worker
     выкатывается особым путём (номер `VERSION`, корень пула — `docs/browser-infra-notes.md`),
     поэтому сам не выкатывай, предложи.
4. Дай координатору цифры для решения по пилотам `FLASH_SEARCH` и `BROWSER_FAST` для
   всех.
