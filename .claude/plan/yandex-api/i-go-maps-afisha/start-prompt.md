# Единица `i-go-maps-afisha`: операции Go, Карт и Афиши в инструменте `yandex`

Ты добавляешь операции Яндекс Go, Карт и Афиши в готовый каркас инструмента
`yandex`, и только их. Каркас (транспорт, реестр, флаг) уже в `bro-next`
(PR #355), спецификации — `docs/yandex-api/go.md`, `maps.md`, `afisha.md` с
фикстурами `tests/fixtures/yandex/{go,maps,afisha}/` (PR #358).

Координатор — сессия `session_01NEromtYDiw5mtYrLKHCiwU` (сообщения ей —
`send_message`). Параллельно идут `i-food` и `i-market` (`agent/lib/yandex/food/`,
`agent/lib/yandex/market/`, по строке в `registry.ts`). Чужие файлы не трогай;
конфликт в `registry.ts` при слиянии решает координатор.

## Что сделать

Папки `agent/lib/yandex/go/`, `agent/lib/yandex/maps/`, `agent/lib/yandex/afisha/`
(нижний регистр, файлы по роли), по строке в `registry.ts`. Origin каждой
операции — страница её сервиса из спецификации (функция страницы ходит только на
свой origin).

Операции (все `access: "read"`, id — как в спецификациях):

- `go.estimate` (цена и подача по тарифам между двумя адресами; геокодирование —
  как в спецификации), `go.rides` (последние поездки). Вызов такси — нет: в
  `about` скажи модели, что заказать машину этим инструментом нельзя.
- `maps.search`, `maps.org` (карточка, до 3 отзывов коротко, свободные слоты
  брони на дату — только чтение; бронировать — `browser_task` с согласием
  человека).
- `afisha.search`, `afisha.tickets`.

Правила:

- `run` — строка с async-функцией `(args) => ответ`, перенеси JS из
  спецификации: аргументы — параметром, не константой; ответ —
  `{status: "ok", data}`, `{status: "signed_out"}`, `{status: "captcha"}` как
  в спецификации. Ужимание — внутри функции (до 10 элементов, только поля для
  человека). Подпись `s=` Карт и получение csrf — внутри `run`.
- Аргументы-идентификаторы (id организации, slug события) — схемой zod с
  простым шаблоном (`^\d+$` и т. п.); ссылки на чужие хосты не принимать.
- `result` — zod-схема ужатого ответа. userId, csrf, телефон водителя, полный
  адрес дома в истории поездок в результат не включай (откуда-куда — коротко,
  как в спецификации).
- Юнит-тесты: для каждой операции — выполнение `run` в `node:vm` против
  фейкового `fetch` (и `indexedDB`/`document`, где нужно), который отдаёт
  фикстуру, и проверка `result`; тест подписи `s=` на известном примере из
  спецификации; тест на `signed_out`. Если в `bro-next` уже есть общий помощник
  для таких тестов (из `i-food`/`i-market`) — переиспользуй его.
- oxlint `anti-slop`: без `unknown`-параметров, `typeof`-ветвлений и
  `Record<string, unknown>` в TypeScript (в строке `run` — обычный JS).

## Заметки координатора

- Ничего не придумывай сверх спецификаций: «не удалось» — операции или поля нет.
- Живьём операции проверит координатор после выката; чтение через `cdp.py eval`
  (см. `PROTOCOL.md`) — можно, ничего не заказывать и не бронировать.
