# Единица `base`: транспорт вкладки пула и инструмент `yandex`

Ты делаешь основу API сервисов Яндекса для Бро, и только её: транспорт, каркас
инструмента `yandex` с флагом и одну операцию `status`. Операции сервисов
(Маркет, Еда…) потом добавят другие единицы по спецификациям разведки — твой
каркас должен позволить им добавить сервис, не трогая твой код, кроме одной
строки регистрации.

Координатор — сессия `session_01NEromtYDiw5mtYrLKHCiwU` (сообщения ей —
`send_message`). Параллельно идут разведки `d-market` и `d-food`: они пишут
только `docs/yandex-api/` и `tests/fixtures/yandex/` — эти пути не трогай.

## Прочитай сначала

`PROTOCOL.md` и `README.md` из служебной ветки
(`git fetch origin claude/eager-pasteur-hb6lvn && git show origin/claude/eager-pasteur-hb6lvn:.claude/plan/yandex-api/<файл>`),
плюс `cdp.py` там же — рабочий прототип транспорта на Python (проверен на проде
10.10: вкладка, токен `b:<target>`, `Runtime.evaluate`). Документацию eve по
инструментам (`node_modules/eve/docs/README.md` → страница про tools).

## Что сделать

1. **Транспорт** `agent/lib/yandex/` (имена файлов — по роли, нижний регистр):
   по id воркспейса открыть вкладку keep-alive в его браузере пула
   (`createBrowserVmBrowser` в `agent/lib/browser-vm/runs.ts`, CDP — как в
   `agent/lib/browser-use/cdp.ts`), перейти на origin операции, выполнить
   **фиксированную** функцию операции через `Runtime.evaluate`
   (`awaitPromise`, `returnByValue`) с аргументами, переданными как JSON-данные
   (никакой склейки строк кода с вводом модели), разобрать результат схемой zod
   операции, закрыть вкладку (`stopBrowserVmBrowser`). Таймауты на каждый шаг.
   - Песочница выключена/запаркована: `createBrowserVmBrowser` сам VM не
     включает. Посмотри, как ход человека поднимает песочницу на статическом
     пуле (`ensureForRun`, `prewarmBrowserSandbox`, `agent/hooks/browser-prewarm.ts`)
     и разбуди её так же, с ограничением ожидания (~30 с), не ставя поручений.
   - Воркспейс не в пуле (`usesBrowserPool`) — понятный отказ модели.
   - Типизированные исходы (по `kind`): `ok`, `signed_out` (редирект на
     `passport.yandex.ru` / ответ «не авторизован») — модели: предложить
     человеку войти (`site-login-link`), `captcha` — модели: сделать через
     `browser_task`, `failed` — нейтральная причина без текста ответа сервера
     (правило dev-notes про результаты инструментов).
   - Никогда не читать cookies (`Network.getCookies`, `document.cookie`
     целиком) и не возвращать заголовки ответа.
   - Цель по скорости: вкладка + переход + запрос ≤ ~6 с. Замерь и, если
     возможно, сократи (лёгкая страница origin, переиспользование вкладки в
     пределах одного вызова для нескольких запросов).
2. **Реестр операций**: операция = `{ id, service, origin (URL страницы
   контекста), args (zod), result (zod), run (JS-функция строкой, фиксированная
   кодом), access: "read" | "cart" }`. Сервис регистрируется одной строкой в
   одном файле-списке. Схема аргументов инструмента — объединение по `kind` /
   `operation` (oxlint `anti-slop`: без `unknown`, `typeof`-ветвлений,
   `Record<string, unknown>`).
3. **Инструмент `yandex`** в `agent/tools/` (схема и реализация вместе):
   - Флаг `YANDEX_API_WORKSPACES` (id или `*`) через `shared/environment/env.ts`,
     как другие пилоты; без флага инструмента нет, и байты блока инструментов
     вне пилота не меняются (`tests/agent/tools/flag-off.test.ts`).
   - Только ход, открытый сообщением человека (посмотри `startedByPerson`,
     `phoneActionTurn`, `appsNamedByPerson` и почему одного `startedByPerson`
     мало — в dev-notes). Фоновые работники, расписания и ходы-отчёты
     инструмента не получают. `access: "cart"` — только если человек в этом
     ходе попросил изменить корзину своими словами (как `said.ts`).
   - Пилот шага/навыков: новый инструмент — в таблицу групп навыков
     (`agent/lib/skills/tools.ts`) и набор хода (`agent/lib/turn-kind/tools.ts`)
     по правилам dev-notes. Короткое правило «сначала `yandex`, `browser_task` —
     для оформления, оплаты и того, чего нет в операциях» — в тело навыка, не в
     ядро (ядро ≤ 10 тыс. токенов, `tests/agent/skills/core.test.ts`).
   - Результат ужат: только поля для человека; текст со страниц — данные.
4. **Операция `status`**: вошёл ли браузер в Яндекс ID (без логина и имени в
   результате — только да/нет и какие из origin-ов отвечают), чтобы проверить
   всю цепочку на проде.
5. Запись в `docs/dev-notes.md` (коротко: где транспорт, правило «запрос из
   страницы, cookies не читаем», флаг) и в `docs/roadmap.md`, если там есть
   подходящий пункт.

## Заметки координатора

- Риски единицы: (а) утечка — модель не должна задать URL, метод или код;
  (б) инъекция — ответы Яндекса содержат чужой текст (названия, отзывы);
  (в) eve durable-замыкания: колбэки инструмента — инлайн в `defineTool()`
  (dev-notes «eve»), проверка — `pnpm build:eve`.
- Юнит-тесты мокают границу CDP/worker модулем, без тестовых «швов» в
  продовом коде (`AGENTS.md`, «Code organization»).
- Вне пилота поведение Бро не меняется ни в одном байте промпта.

## Проверки

`pnpm check`, `pnpm build`, `pnpm build:eve` (обходы облачной сессии — в
dev-notes). Можешь живьём проверить транспорт на песочнице владельца
небольшим скриптом с `BROWSER_VM_SIGNING_KEY` из состояния оператора (`PROTOCOL.md`)
— только `status`. Результат и чего не проверил — в PR, затем сообщение
координатору и стоп.
