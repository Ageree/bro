# U3b. Страница владельца `/workspace/admin`

Ты делаешь только этот юнит. Сначала — `.claude/plan/PROTOCOL.md`.

## Зачем

Владелец открывает бету и хочет видеть всё, что происходит у пользователей.
U3a (уже в `bro-next`, см. его PR) пишет журнал ходов, тексты под флагом
`OWNER_TRANSCRIPTS` и сервис чтения в `db/services/…`. Ты делаешь страницу,
которая его показывает.

## Что сделать

- Доступ: только владелец. Env-список id пользователей или email владельца
  (`ADMIN_USER_IDS`, через `shared/environment/env.ts`). Остальным — 404, не
  403, и пункта в навигации нет. Проверка — на сервере (страница и tRPC),
  не в клиенте. Тест: обычный пользователь не получает ни страницу, ни
  данные через tRPC.
- `/workspace/admin`: таблица людей — имя или телефон, каналы, дата
  регистрации, последняя активность, ходы и сбои за 24 ч и 7 дней, расход в
  рублях за день и месяц. Сортировка по последней активности.
- `/workspace/admin/<workspace>`: ходы — время, канал, вид, длительность,
  инструменты, исход и код ошибки, цена. Фильтр «только сбои». У хода —
  раскрытие текста (если тексты есть), иначе пометка «тексты выключены».
- Строится на примитивах `web/components/ui` и `type-*`
  (`AGENTS.md`, «Design system»), рядом с существующими разделами
  `app/(authenticated)/workspace/`. Данные — через tRPC, как остальной
  кабинет (`web/trpc/router.ts`).
- Страница должна работать на телефоне: владелец смотрит с него.

## Ловушки

- `app/` не импортирует `agent/` (правило `no-forbidden-layer-imports`).
- Не грузи все тексты списком: текст хода — по запросу.

## Проверка

Тесты доступа и сервиса, `pnpm check`, `pnpm build`. Скриншот страницы на
мобильной ширине с тестовыми данными — в PR (локальный `pnpm dev` с PGlite
или dev-базой; если не выйдет, напиши почему).
