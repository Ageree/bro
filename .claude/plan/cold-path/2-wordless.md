# Задание 2: не учить операции, в адрес которых не попадают слова поиска

Ветка: `claude/site-wordless-ops`. Версия worker: `2026-10-26.8`.
Сначала прочитай `.claude/plan/cold-path/PROTOCOL.md` из этой же ветки.

## Что видели (замер 26.10 на проде, 32 незнакомых сайта, worker 2026-10-26.6)

- zoozavr.ru: поиск строкой сайта ответил верно (16 карточек за 8,8 с) и выучил операцию
  `zoozavr.ru/search/results/%id%/` — в адресе выдачи id поиска, который сайт выдал этому одному
  поиску (форма → редирект на `/search/results/<id>/`), а не слова. Второй поиск: модель
  заполнения выбрала её, заполнила `%id%` чем-то и упала на `fit` → браузер (строка
  `[site-api] left to the browser`, `reason: 'fit'`, `offered: ['zoozavr.ru/search/results/%id%/']`).
- hoff.ru: выученная операция `hoff.ru/nsk/catalog/gostinaya/divany/` — страница одной категории
  без места для слов; модель заполнения не взяла (`chose: null`, `reason: 'no_operation'`).

Такая операция не может нести слова другого поиска: она тратит вызов модели заполнения и,
занимая сайт, не пускает туда холодный путь (взгляд строкой сайта), хотя тот у этого сайта
работает.

## Что сделать

1. Worker: операция, выученная из поиска со словами (взгляд `/v1/look`, конец поручения), где
   слова поиска не легли ни в одно место шаблона (путь `%query%`/`%word%`, ключ query, поле тела
   запроса) — ни сами, ни транслитом (superjob `/vakansii/<слова транслитом>`), — не отдаётся
   Бро. Место, взявшее id поиска, сессию, хэш, — не место для слов.
2. Бро: такие операции, уже лежащие в базе (`browser_site_operations`, свои и общие), не
   предлагаются модели заполнения для поиска и не мешают холодному пути: сайт, у которого нет ни
   одной операции, способной нести слова, идёт как сайт без операций (`lookSite`). Решай по
   шаблону, без миграции, если хватает. Просмотренные операции (`known.ts`) и находки с живых
   сайтов из dev-notes (hh, ostrovok, citilink, rabota, zarplata, drom, auto.ru, letu, labirint,
   petrovich, kinopoisk, tutu, wb) должны остаться в работе — проверь каждую по её шаблону.
   Осторожно с шаблонами, где слова — город/рубрика словом (`/hotel/russia/kazan/`, `%word%`):
   они нужны.

Проверка: тест, который падал до правки, на стороне worker (операция zoozavr-вида не
выучивается, обычная `?q=%query%` — выучивается) и Бро (сайт только с такой операцией идёт в
холодный путь). Если на стенде zoozavr.ru открывается — замер двух разных поисков подряд.
