# Промпт следующей сессии по файлам

Вставить в новую облачную сессию Claude Code (репозиторий Ageree/bro). Номер телефона
владельца для входа владелец добавит сам, в репозиторий его не кладём.

---

Продолжи работу над файлами и подписью Бро. Что выкачено, последний результат каждого кейса и
открытые вопросы — `docs/benchmarks/files/status.md` в `bro-next` (прочитай целиком). Как гонять
набор — `docs/benchmarks/files/README.md`.

Режим работы: я заранее выдал все разрешения на всё, что описано в `docs/dev-notes.md`
(«Процесс»): код, слияние в bro-next при зелёном CI, выкат на прод, env прода, ops-скрипты,
база прода. Не переспрашивай, спрашивай меня только о том, что могу лишь я (код из SMS, ключ из
кабинета, пополнение).

1. Перед любой работой войди в мой аккаунт Бро: `pnpm bench` вход по телефону (номер дам в
   чате), код из SMS попроси у меня. Без входа не начинай.
2. Проверяй всё реальными тестами на реальной инфраструктуре: прод brobro.tech, набор f-* через
   `pnpm bench run --suite files`, кейсы строго по одному. Юнит-тестов и ревью мало: изменение
   считается сделанным, когда кейс прошёл на проде.
3. Полный прогон 17.10 — 25 из 30 кейсов целиком (`status.md`). Сначала перегони кейсы, упавшие
   в последнем прогоне (столбец «Проверки» без жирного), затем весь набор. Упавшие кейсы — разбор
   причины: несправедливую проверку чини в проверке, остальное — в Бро, помощнике или наборе,
   общим правилом или страховкой в коде набора, а не под один кейс.
4. Одна пачка правок → PR → слияние → выкат → прогон только упавших кейсов. Повторять, пока
   кейсы не пройдут или причина не окажется вне нашего кода.
5. Обновляй `status.md` по ходу и в конце: таблица «было/стало» и что осталось.
6. Береги токены: субагентов — по делу, без многократных ревью одного и того же; прогоны —
   только упавших кейсов. Цена кейса — `usage-stats.sh` за его окно (`status.md`, «Как гонять»).
