Продолжи работу над файлами и подписью Бро. Где остановились, что выкачено и что сломано —
`docs/benchmarks/files/status.md` в ветке `claude/vibrant-wright-77fgy4` (прочитай целиком).
Как гонять набор — `docs/benchmarks/files/README.md`.

Режим работы: я заранее выдал все разрешения на всё, что описано в `docs/dev-notes.md`
(«Процесс»): код, слияние в bro-next при зелёном CI, выкат на прод, env прода, ops-скрипты,
база прода. Не переспрашивай, спрашивай меня только о том, что могу лишь я (код из SMS, ключ из
кабинета, пополнение).

1. Перед любой работой войди в мой аккаунт Бро: `pnpm bench` вход по телефону (номер дам в
   чате), код из SMS попроси у меня. Без входа не начинай.
2. Проверяй всё реальными тестами на реальной инфраструктуре: прод brobro.tech, набор f-* через
   `pnpm bench run --suite files`, кейсы строго по одному. Юнит-тестов и ревью мало: изменение
   считается сделанным, когда кейс прошёл на проде.
3. Сначала доведи черновик из ветки (роутер Jev для помощника и подпись без `ask`): исправь
   пункты «До слияния обязательно» из `status.md`, `pnpm check` и `pnpm build:eve`, PR, слияние,
   выкат.
4. Потом проблемные кейсы из `status.md`, «Причины провалов»: исправь причину, а
   несправедливую проверку — проверку. Сначала то, что помечено [Бро] и [помощник].
   Одна пачка правок → PR → слияние → выкат → прогон только упавших кейсов. Повторять, пока
   кейсы не пройдут или причина не окажется вне нашего кода.
5. Флаг роутера помощника: сначала мой воркспейс, после зелёного прогона — `*`.
6. Обновляй `status.md` по ходу и в конце: таблица «было/стало» и что осталось.
7. Береги токены: субагентов — по делу, без многократных ревью одного и того же; прогоны —
   только упавших кейсов.
