# Телефония Бро: проектирование и проверка провайдеров

Статус: backend реализован; включение и доставка в production выполняются оператором.
Проверка API и публичных условий — 6 октября 2026 года. Успешное чтение API
не доказывает возможность купить номер, установить SIP-соединение или
провести разговор. Эти проверки выполняются отдельно на одном пилотном номере.

## Продуктовый контракт

У пользователя после включения телефонии появляется отдельный постоянный
российский телефонный номер. Бро звонит с него по явно данному поручению,
принимает обратные звонки и возвращает результат в тот разговор, где получил
поручение. Номер общего iMessage-канала не меняется. SIP ID, внутренний
добавочный номер и общий исходящий номер не заменяют индивидуальный номер.

Новым пользователям номер выделяется автоматически при создании workspace, за счёт платформы, когда оператор включил auto-provision. Существующие аккаунты не получают массовый backfill; для них остаётся отдельно подтверждённая активация.
Выключение исходящих звонков и освобождение номера — разные операции:
выключенный, но сохранённый номер продолжает оплачиваться. Освобождение
требует отдельного подтверждения; нельзя незаметно менять номер пользователя
или передавать его другому пользователю Бро.

Телефонный собеседник слышит, что разговаривает с ИИ-помощником, действующим
по поручению человека. Голос не имитирует владельца. Поручение ограничивает
полномочия: возможность поговорить не даёт права совершать платежи,
соглашаться на дополнительные расходы или раскрывать другие данные человека.

## Провайдеры и стоимость

Проверенный API Exolve предлагает обычные мобильные номера Москвы за
600 ₽ подключения и 155 ₽/месяц. Проверенные городские номера Москвы и
Санкт-Петербурга стоят 990 ₽ и 210 ₽/месяц. Это предложения конкретного
аккаунта, не обещание неизменного тарифа: перед подключением нужно заново
проверять стоимость и доступность. Отсутствие необходимости в SMS само по
себе не делает городской номер дешевле мобильного.

Дополнительная проверка 59 других регионов каталога (118 запросов обычных
DEF/ABC, по одному доступному предложению) более дешёвых вариантов не нашла:
20 доступных мобильных предложений имели те же 600/155 ₽, 54 городских —
990/210 ₽; в остальных выборках не было наличия. Наличие входящей и исходящей
голосовой связи проверялось у каждого предложения. Это выборка обычных
номеров, не проверка каждого номера в каталоге; порядок учёта НДС API не указал.

Публичные тарифы исходящих звонков указывают 1,76 ₽/мин на мобильные РФ и
0,85 ₽/мин на городские Москвы и Санкт-Петербурга, с округлением неполной
минуты вверх. Маркировка, автоматизированные вызовы, запись и иные услуги
могут тарифицироваться отдельно; перед массовым включением нужен полный
тариф коммерческого аккаунта, а не только базовая цена минуты.

Первым трём SIP ID соответствует бесплатное обслуживание; публичная цена
следующих — 95 ₽/месяц за SIP ID. Поэтому один SIP ID на пользователя нельзя
считать бесплатным при масштабировании. Предпочтительный вариант — общий
транспорт с выбором принадлежащего приложению исходящего номера на каждый
вызов. Документация допускает такой выбор, но точный способ передачи номера
и совместимость с ElevenLabs ещё требуют проверки. Менять общий
`SetDisplayNumber` перед каждым звонком нельзя: параллельные звонки разных
пользователей получат чужой номер.

В живом каталоге ElevenLabs и схеме Agents доступны `eleven_v4` и
`eleven_v4_turbo`, оба поддерживают русский язык. Для разговора выбран
`eleven_v4_turbo`: вариант для низкой задержки с выразительной речью. Наличие
модели в каталоге не заменяет проверку синтеза и слышимого разговора.

У отдельного TTS Turbo имеет коэффициент стоимости 0,5 против 1,0 у v4.
Это не означает, что минута hosted Agents стоит вдвое дешевле. Публичный
Starter Agents: 6 USD/месяц, 75 включённых минут и 6 одновременных разговоров;
дополнительные минуты — 0,08 USD, burst — 0,16 USD. LLM и оператор оплачиваются
отдельно. API подписки показал активный Starter, но не установил остаток
минут Agents или разрешение на их перерасход.

Модель себестоимости одного активированного пользователя:

- Аренда его номера и, если понадобится, отдельного SIP ID.
- Доля общей подписки ElevenLabs, минуты Agents и стоимость LLM.
- Минуты Exolve с его округлением и дополнительными услугами.
- Разовое подключение номера, отдельно от ежемесячной себестоимости.

Экономия начинается с отложенного выделения номера, общего транспорта,
отключённого burst и ограничений длительности и количества звонков.
Уникальные постоянные номера всё равно требуют аренды каждого номера.

## Голосовой тракт

Кандидат на прямое соединение:

1. Exolve предоставляет номер и SIP-учётные данные для исходящих звонков.
2. ElevenLabs импортирует номер как `sip_trunk`, используя SIP digest,
   а не HTTP API-ключ Exolve в качестве SIP-пароля.
3. Бро запускает исходящий разговор через
   `/v1/convai/sip-trunk/outbound-call` с номером назначения и контекстом
   конкретного поручения.
4. Входящие на выделенный номер Exolve переадресует на идентификатор
   этого номера в `sip.rtc.elevenlabs.io`; ElevenLabs принимает разговор.
5. Бро сохраняет результат, сверяет его с API провайдера и доставляет отчёт.

Прямой исходящий тракт доказан с отдельной outbound identity по raw SIP login:
ни REGISTER, ни отдельный SBC не потребовались. Public DID сохраняется для
входящих и Caller ID; обе identities связываются с одним оплачиваемым номером.
Человеческий входящий PSTN callback остаётся отдельной проверкой. Статические
SIP-адреса ElevenLabs доступны Enterprise, поэтому их нельзя считать
бесплатным решением для Starter.

В актуальной таблице Exolve SIP ID и Static IP недоступны физическим лицам
и временно недоступны в тестовом режиме. Старые инструкции тестового режима
этому противоречат. Возможность коммерческого использования, договор и
допустимую модель закрепления номеров за пользователями необходимо установить
до массового подключения; API-ключ и положительный баланс этого не доказывают.

## Границы данных и полномочий

База связывает workspace, выделенный номер, импортированный номер ElevenLabs
и звонки. Ни модель, ни входящий webhook не выбирают произвольный workspace.
Исходящий номер выводится из аутентифицированного workspace; доступ к звонку
проверяется по его владельцу, а не только по идентификатору провайдера.

Общий голосовой агент получает инструкции конкретного поручения только через
данные конкретного разговора. Нельзя обновлять общий системный промпт перед
звонком. В ElevenLabs передаются только необходимые этому собеседнику факты,
а не вся память, переписка, секреты или профиль владельца.

Входящий Caller ID не подтверждает личность: его можно подменить. Без
дополнительного подтверждения входящий агент только представляется,
принимает сообщение и передаёт его владельцу. Чтобы продолжить конкретное
поручение, можно выдать собеседнику случайный код во время исходящего звонка.
Сервер проверяет срок, количество попыток и привязку к вызываемому номеру;
только затем открывает минимальный контекст этого поручения. Код не должен
заранее присутствовать в промпте входящего агента. Входящий собеседник не
может запустить новые поручения, менять разрешения или читать память человека.

Исходящий `phone-call` набирает только номер, который человек сам написал в
текущем ходе, либо телефон контакта, названного человеком в этом ходе и
возвращённого `contacts-search` в нём же (форматы `+7 999 123-45-67`,
`8 999 1234567`, `9991234567` — один номер). Номер из письма, страницы,
отчёта задачи или браузера и сводки входящего звонка не считается: Бро просит
подтвердить номер в чате. Правило проверяют и approval, и execute
(`agent/lib/phone/destination.ts`), слова человека замыкание берёт на
`step.started`. За ход человека — не больше двух звонков, параллельные вызовы
шага считаются по записанным действиям (`phoneActionsBefore`).

Инициализация входящего разговора использует отдельный секрет в HTTP-заголовке.
Её настройка в ElevenLabs общая для аккаунта, а использование включается
для отдельных агентов; существующие интеграции нельзя перезаписывать.
Завершение разговора проверяется отдельно: HMAC заголовка
`ElevenLabs-Signature` над исходным телом, допустимое время подписи и
устранение повторной обработки. Ни один секрет не возвращается модели.

## Надёжность и лимиты

Перед внешним вызовом сохраняются намерение и идентификатор операции.
Повтор того же вызова инструмента возвращает
имеющийся результат, а не звонит заново. У API исходящего звонка нет
документированного ключа идемпотентности: неопределённый сетевой результат
сначала сверяется с провайдером. Истечение тайм-аута не разрешает повторный
звонок. Аналогично покупка номера сверяется с инвентарём до повторной покупки.

Приложение не устанавливает ограничения количества, per-user concurrency,
месячных минут или отдельную максимальную длительность: действуют технические
настройки и пределы провайдера. Цель должна быть российской, а поручение —
явным и аутентифицированным. Неопределённость не разрешает автоматический redial.
Неизвестная стоимость не записывается как нулевая. Цена ElevenLabs
`metadata.cost_fiat` и операторский счёт Exolve учитываются отдельно.

Ответ API о принятии звонка не означает, что трубку сняли. Статус `done`
не означает выполнения поручения: автоответчик или неудачный разговор тоже
могут закончиться штатно. В отчёте различаются результат соединения,
результат поручения, неопределённый исход и необходимость ответа владельца.

Webhook сохраняется до подтверждения приёма. Периодическая сверка API
восстанавливает пропущенные события; доставка отчёта имеет собственное
состояние и повторяется при недоступности чата без повторного звонка.
Отчёт поступает как фоновое сообщение от системы, а не новое распоряжение
человека. Исходящие действия по тексту телефонного собеседника запрещены.

## Приватность и жизненный цикл

У ElevenLabs для пилота отключается сохранение аудио, а срок хранения
ограничивается. Удаление данных у одного провайдера не удаляет их у другого
или из уже доставленного отчёта. До обещания режима без записи нужно
проверить условие Exolve о записи на новом номере в первые 30 дней.

Деактивация, удаление аккаунта и освобождение номера должны оставлять
восстановимую операцию отключения внешних ресурсов. Простое каскадное
удаление строки БД не прекращает аренду у провайдера. Данные прежнего
владельца никогда не становятся контекстом нового владельца номера.

## Проверки до включения

Проверяется реальная связка: покупка одного номера, создание SIP и агента,
один ограниченный исходящий звонок разрешённому тестовому получателю,
обратный звонок, слышимость в обе стороны, русский голос, прерывания,
завершение, идентификация номера и получение отчёта. Посторонним не звонить.

Отдельно нужны реальная проверка подписи webhook, изоляция двух workspace,
повторная доставка, пропущенное событие, неопределённый запуск, отказ
по лимиту и сохранение состояния после перезапуска. Моки ответов провайдера
не заменяют эти результаты. Расширение за пределы владельца допускается
только после пилота, с выключенным по умолчанию флагом доступа.

## Реализованный backend и операторский запуск

Backend реализован за пилотным флагом; это ещё не подтверждение готовности
полного телефонного продукта. `agent/agent.ts` и имя пакета
`local-vault-assistant` не меняются. В чат входят `phone-quote`,
`phone-activate`, `phone-call`, `phone-status`, `phone-disable`,
`phone-enable` и `phone-release`; UI для этого не нужен.

`PHONE_WORKSPACES` — id через запятую или `*` для всех. Без списка телефония выключена. `PHONE_AUTO_PROVISION=on` — отдельное, выключенное по умолчанию разрешение платформы оплачивать новые номера: только создание нового workspace транзакционно ставит один запрос в очередь, повторный login и существующие пользователи не создают новых покупок. Работник расписания выделяет номер вне signup-транзакции; нехватка денег или preflight не ломают регистрацию и получают backoff. Неоднозначный оплачиваемый POST сверяется, но не повторяется. До готовности status показывает pending/retry, а не выдуманный номер. Карточка активации/оплаты новому auto-аккаунту не нужна.

Нужны MTS_EXOLVE_API_KEY, ELEVENLABS_API_KEY, PHONE_AGENT_ID, PHONE_INIT_SECRET, PHONE_WEBHOOK_SECRET, включённые расписания Eve и DATABASE_DRIVER=node-postgres. В Cloud.ru для ElevenLabs нужен отдельный ELEVENLABS_PROXY_URL: авторизованный egress, TLS-проверка включена, без изменения глобального или браузерного dispatcher. Секреты не печатают.

Количество звонков не ограничивается приложением: нет дневных/месячных call-квот, target allowlist или произвольного per-user concurrency cap. Ограничение целей — полный российский +7 с национальным префиксом 3, 4, 8 или 9; Казахстан, экстренные короткие номера и премиальные +7803/+7809 отсекаются. Разные явные поручения могут идти параллельно, но повтор одного operationId возвращает тот же job и не дублирует POST. Длительность берётся из действующей настройки провайдера, не из трёхминутного app-cap; 60 секунд — только операторский live-pilot. Технические пределы самого аккаунта/провайдера сохраняются и сообщаются честно.

Ограничения покупки ресурсов сохраняются: свежие per-number setup/monthly/SIP fee caps и проверка кошелька. PHONE_MAX_ACTIVE_NUMBERS — необязательный операторский resource cap без скрытого потолка 10; если не задан, приложение не вводит лимит пользователей. Глобальная аренда provisioning сериализует покупки и проверки средств. До первого доверенного чата recipient/session не выдумываются: входящий отчёт хранится, пока first-person session не привяжет реальный маршрут; затем retries отсчитываются от первой доставки, а не от даты signup.

Сначала оператор проверяет отдельного голосового агента. Скрипт по умолчанию
только читает; изменение требует `--apply`, новый приватный выходной файл
создаётся с режимом 0600. Секреты не передают аргументами и не печатают.
Для операторских команд используйте Node 24 с `--experimental-transform-types`:
зависимость `adopt.ts` содержит TypeScript parameter property, которую
strip-only режим не исполняет.

```sh
node --env-file=.env.local --experimental-transform-types \
  scripts/phone/setup.ts --public-url https://your-domain

node --env-file=.env.local --experimental-transform-types \
  scripts/phone/setup.ts --public-url https://your-domain \
  --apply --output "$HOME/.capy/work/bro-phone.env"
```

Скрипт меняет только явно выбранного агента Бро и его HMAC-hook, не общие
настройки других агентов. Он включает русский `eleven_v4_turbo`, разрешённые
override полей prompt/first message/max duration, безопасный системный
`end_call`, signed-URL аутентификацию без публичного origin allowlist,
ограниченное хранение данных и fetch initiation-data. Действующие технические настройки провайдера не превращаются в app-квоты: native concurrency -1, daily default 100000, без bursting. Существующая provider duration сохраняется; явный --duration-seconds меняет её только в операторском setup.

У пилота уже куплены номер и SIP и импортирован номер ElevenLabs. Второй
покупать нельзя. Для явной привязки существующих, проверенных ресурсов
служит read-only операторский `adopt.ts`: он сверяет владение DID, SIP,
trunk, агента, переадресацию и текущую плату, а затем записывает привязку в
указанное существующее пространство и принадлежащую ему сессию. Для
мессенджера должен уже существовать доверенный записанный маршрут.

```sh
node --env-file=.env.local \
  --env-file="$HOME/.capy/work/bro-phone.env" \
  --experimental-transform-types scripts/phone/adopt.ts \
  --workspace '<exact-workspace-id>' --number '+7XXXXXXXXXX' \
  --number-id '<verified-exolve-number-id>' --sip-id '<verified-sip-id>' \
  --phone-number-id '<verified-elevenlabs-inbound-id>' \
  --outbound-phone-number-id '<verified-elevenlabs-outbound-alias-id>' \
  --session-id '<owned-eve-session-id>' --channel eve \
  --paid-setup-rub 600 --confirm-existing-paid-number
```

До команды проверьте целевую БД, id владельца/сессии и значения окружения:
Node `--env-file` не заменяет уже заданные переменные процесса. Для повторного
setup загружайте сохранённый приватный receipt, чтобы сверить существующий
hook, а не создавать новый после неоднозначного ответа.

У уже импортированного пилотного DID входящий `allowed_numbers` намеренно
ограничен только тестовым телефоном владельца. Adoption это ограничение
сохраняет. Перед обратными звонками клиник или ресторанов оператор должен
явно убрать тестовый caller-фильтр после проверки безопасности; существующий
пилот не принимает любые обратные звонки по умолчанию. Новые импорты
предусматривают любые caller numbers за carrier IP ACL и локальными лимитами.

Входящий Caller ID сохраняется лишь как ограниченный E.164 контакт с отметкой
«не проверен», если провайдер его предоставил. Он может быть подменён и не
выбирает владельца, не даёт доступа к памяти и не разрешает перезвонить.
Скрытый или неизвестный номер остаётся `null`. Решение перезвонить принимает
только владелец в новом явном поручении, с той же проверкой российской цели.

Отчёт доставляется отдельной арендой, а не повторным звонком. Текущий token,
владелец и факт доставки проверяются перед реальным сообщением/реакцией;
старые отложенные отчёты не могут отправиться после смены token. Неудачи
получают возрастающую задержку от минуты до часа; автоматические попытки
ограничены десятью и 24 часами. После этого итог остаётся доступен через
`phone-status`, в том числе по `callId`.

## Что реально проверено и чего ещё нет

Локальные проверки используют настоящий Postgres, не имитацию ответов
провайдеров: конкурентные дубликаты, ровно один старт, изоляция владельцев,
параллельные отдельные намерения без app-квот, Caller ID без полномочий, атомарное истечение
планируемого задания, token A/B на реальном messaging executor/Eve ALS,
повторы и запрет каскадного удаления платного ресурса.

```sh
PHONE_TEST_DATABASE_URL=postgresql://postgres@127.0.0.1:55432/phone_integration \
  NODE_OPTIONS=--max-old-space-size=1536 RAYON_NUM_THREADS=1 \
  pnpm exec vitest run tests/agent/phone.integration.test.ts \
  agent/lib/phone/tests/policy.test.ts app/api/phone/ingress.test.ts \
  --maxWorkers=1 --no-file-parallelism
```

Тестовая БД должна называться `phone_integration` и находиться на localhost;
production URL отклоняется. Миграцию `0053_phone.sql` применяют перед
тестом. Обязательные итоговые проверки — `pnpm check`, `pnpm build` и
`pnpm build:eve`, последовательно. Файлы `.eve`, приватные env, журналы и
внешний HTTP-harness не входят в коммит.

Реальная операторская проверка отдельного прямого SIP-тракта установила:
при выключенной привязке initiation отвечает HTTP403, и настоящий SIP-сеанс
заканчивается 502 без принятого разговора, transcript и строк звонков.
При включённой той же привязке прямой SIP получил 200, длился 17 секунд,
дал приветствие агента и UDP-медиа (522 исходящих и 845 входящих пакетов).
Создана ровно одна строка правильного workspace; provider `user_id` совпал
с её локальным UUID. Получен настоящий подписанный
`post_call_transcription`, записанный один раз. В реальной расшифровке есть
предупреждение «Оператор связи может записывать…». `cost_fiat` этой проверки —
0.0089109 USD, не RUB.

Дальнейший реальный исходящий вызов установлен через вторую ElevenLabs identity: существующий public DID остаётся inbound phoneNumberId, а raw OWN SIP login без '+' используется только как outboundPhoneNumberId. Это тот же один оплаченный DID и SIP, не новый номер. MTS требует SIP login в From: public DID воспроизводит 480, raw login даёт звонок. Нативный человеческий разговор подтверждён: 32 секунды, два подтверждения слышимости получателем, gpt-6-luna/v4Turbo, AI/recording disclosure и end_call; MTS CDR answered 32.74 секунд и показывает правильный публичный DID, не login. Carrier charge 1.76 RUB; ElevenLabs примерно 0.01806 USD. SBC/новая VM не нужны. В интерфейсе и отчёте показывают public DID, не raw login; canonical phoneNumberId сверяется по direction (outbound alias / inbound public DID). Обе identities проверяются перед active и удаляются перед освобождением MTS ресурса.

Человеческий входящий PSTN callback пока не наблюдался. Контролируемое выделение номера для действительно нового пользователя требует достаточного кошелька; недостаток средств не маскируется готовностью. Временные preview hooks и локальные fixtures после проверки убирает оператор, не инструменты модели.
