## Этап А: включить пилот (≈ 30 минут)

1. Node 24 и зависимости (`docs/dev-notes.md`, «Процесс»):
   - `npm pack node-linux-x64@24` во временный каталог, его `bin` — в начало
     `PATH`;
   - `pnpm install --frozen-lockfile`;
   - при нужде `apt-get install -y zstd`.
2. Ключи оператора: `python3 scripts/cloudru-app-host/host.py state restore`,
   затем удалить `~/.bro-app-host/token` — восстановленный кэш IAM-токена
   просрочен.
3. В `~/.bro-app-host/env/prod.json` поставьте два ключа. Правьте скриптом
   и печатайте только имена:
   - `BROWSER_FAST_WORKSPACES` — то же значение, что у
     `FLASH_SEARCH_WORKSPACES` (id воркспейса владельца);
   - `BROWSER_HOST_FLAVOR` = `gen-2-8`.
4. Применить env:
   - сначала холостой прогон:
     `host.py env bro-app-1 --profile prod --allow-missing --no-alert-webhook --with-neon --dry-run`;
   - затем та же команда без `--dry-run`;
   - после 09.10 — без `--with-neon` (`docs/cloudru-migration.md`).
5. `host.py state save`.
6. Нужен ли выкат кода? Код пилота уже на проде, если релиз
   `bro-app-1` (`host.py status bro-app-1`) собран не раньше `fef41ca`.
   Иначе:
   - чистый worktree свежего `origin/bro-next`;
   - Node 24 в `PATH`;
   - оттуда `host.py deploy bro-app-1`.

   Без `BROWSER_FAST_WORKSPACES` в env eve на любом релизе ведёт себя как
   до пилота.

7. Проверка:
   - `https://brobro.tech/api/health` отвечает;
   - в `host.py logs bro-app-1 bro-eve` нет «Invalid environment variables»
     и строк `[browser-fast] pilot lookup failed`.

Флейвор на этом этапе ещё ничего не меняет: он действует лишь на новый
хост. Прогретый хост (`BROWSER_HOST_MIN_WARM=1`) живёт, пока не сменится
корень песочницы.

## Этап Б: новый корень песочницы с worker `.6` (по желанию владельца)

Таймаут 25 с и флейвор `gen-2-8` заработают только с новым хостом, а новый
хост появится лишь со сменой корня. Порядок — `docs/browser-pool.md`
(«Корень меняется сменой `BROWSER_SANDBOX_ROOTFS`», пересборка
`rootfs_build.sh`).

Проверьте квоту до смены. У проекта 8 vCPU и 2 публичных адреса, а они уже
заняты: `bro-app-1`, `sbx-code-2` и хост пула (2 + 2 + 4). Новому хосту на
`gen-2-8` нужны ещё 2 vCPU, пока старый не удалён. Посмотрите в
`agent/lib/browser-pool/hosts.ts` (`outdatedRoot`, `keepWarmHostsUp`),
удаляет ли пул старый хост раньше создания нового:

- если нет и квота не влезает — попросите владельца поднять квоту (может
  только он) или выберите тихий час и разберитесь, как пул переживёт
  окно без хоста;
- `bro-app-1` и `sbx-code-2` не удалять никогда.

Выкат корня ставит поручения в очередь на 5–16 минут создания хоста: не во
время замера и не во время чужого живого теста.

## Этап В: замер

1. Узкий ops-скрипт отдельным PR — `scripts/cloudru-app-host/ops/`, по
   образцу `usage-stats.sh` и `db-lib.sh`. Аргументы — id воркспейса и
   момент «с». Печатает по дням и по статусу из `browser_vm_runs`:
   - число запусков;
   - медиану и p90 `finished_at - created_at`.

   Из `usage_costs` строк браузера — рубли на запуск и хосты ответа
   (`units.hosts`). Ни `task`, ни `result`, ни `final_url` не печатать: там
   данные человека. Влить, выкатить, звать
   `host.py ops bro-app-1 <скрипт> <воркспейс> <с>`.

2. База — запуски воркспейса владельца с 01.10 до выката этапа А
   (пул у него с 01.10, flash-поиск — с 04.10).
3. Новые запуски — только чтение и поиск с аккаунта владельца (он же
   аккаунт бенчмарка):
   - подойдут `d03-recommendations`, `uc-en-weekend` и `d02-flights` с
     подсказкой «ничего не заполняй, только найди варианты» — запуск и
     подсказки в `docs/benchmarks/README.md`;
   - не гонять `d01`, `d06`–`d08` (Госуслуги и входы), `uc-tr-hotel`, `d14`;
   - брони и оплаты не подтверждать.

   Можно проще: попросить владельца отправить Бро 5–10 своих обычных
   поисковых поручений.

4. Признаки, что пилот работает:
   - в `units.hosts` пилотных запусков — `together`;
   - нет «validation error for AgentOutput» в журнале и пропавшего подвала
     `RESULT…NEEDS` в итогах.
5. Чего ждём (замеры Selectel, `docs/browser-speed.md`, 2.4):
   - вызов модели — медиана 2,2 с против 5,6 с;
   - поисковое поручение заметно быстрее;
   - вызов модели до вдвое дороже — сверьте рубли на запуск.
