# Браузерные e2e-тесты

Сквозные тесты гоняют настоящий Бро в браузере: вход по телефону, кабинет,
сейф, личные данные и разговор в чате, где отвечает сама модель. Раннер —
[e2e](https://e2e.tester.army/docs) (open source, Apache-2.0) поверх
Playwright. Шаги пишутся двумя способами:

- точными локаторами и `expect` (`screen.getByRole("button", "Войти")`) — там,
  где важна конкретная кнопка или значение;
- целями на естественном языке (`agent.act("open «Сейф»")`,
  `agent.assert("Bro's latest reply names the Louvre")`) — там, где важен
  исход, а не путь к нему, и для проверки сгенерированных ответов.

Шаги `agent.act` после первого прохода записываются в `.e2e/cache/` и дальше
воспроизводятся без модели. `assert`, `waitFor` и `extract` всегда идут к
модели вживую. Модель раннера и модель самого Бро — одна и та же,
`deepseek/deepseek-v4.1-flash` через OpenRouter (`E2E_MODEL`). Прогон всего
набора стоит центы: шаги раннера ≈ $0.002, ходы Бро в чате — ещё 1–3 цента.

## Запуск

```sh
pnpm test:e2e                          # весь набор
pnpm test:e2e e2e/vault                # каталог или файл
pnpm test:e2e --tag smoke              # без ходов Бро
pnpm test:e2e --exclude-tag agent      # то же
pnpm test:e2e --headed --debug         # видно браузер, таблица шагов
```

Раннер сам поднимает приложение — `next dev` на свободном порту `127.0.0.1`
(`e2e.config.ts`, лог — `.e2e/logs/app.log`). Без `E2E_DATABASE_URL` он идёт
через `scripts/dev.ts`: Postgres из `compose.yaml` в Docker, миграции, `next dev`
(то же, что `pnpm dev`, — та же локальная база). С `E2E_DATABASE_URL` раннер
пишет в эту базу; мигрируйте её заранее
(`DATABASE_URL=… DATABASE_URL_UNPOOLED=… pnpm db:migrate`). Только
одноразовая база: набор заводит людей и пишет их разговоры. `E2E_APP_URL`
направляет набор на уже запущенное приложение; вход без кода работает только
в `next dev` на loopback-адресе.

Переменные раннера — в `e2e/env.ts`. Приложению раннер передаёт только `PATH`,
`HOME` и то, что перечисляет `e2e.config.ts`, а не всё окружение. Но
`next dev` сам читает `.env.local`, поэтому локальный прогон видит ваши ключи
(Composio, Photon и прочие). Эталон — CI, где `.env.local` нет.

`OPENROUTER_API_KEY` нужен для шагов `agent.*` и ответов Бро; без него
проходят только тесты без агента (`--tag smoke`, кроме тех, где есть
`agent.act`).

Отчёт — `.e2e/report.json`. По упавшему тесту смотрите
`.e2e/artifacts/…/failure/screen.txt` (дерево экрана на момент сбоя) и трейс
Playwright там же: `pnpm exec playwright show-trace <trace.zip>`.

## CI

`.github/workflows/e2e.yml` гоняет весь набор на PR и пушах в `bro-next`,
которые трогают то, что видит человек или чем отвечает Бро: `app/`, `web/`,
`agent/`, `db/`, `shared/`, зависимости, сам набор. PR только про юнит-тесты,
документацию, `browser-vm/`, `sandbox/` или браузерный пул и песочницу в
`agent/lib/` набор не запускает. Каждую ночь набор идёт на `bro-next` целиком:
так ловятся смены модели и её хостов, которые приходят без коммита. Новый
каталог с кодом страниц или ответов Бро добавьте в `paths` workflow; вручную
набор запускается через Actions → E2E → Run workflow.
Postgres — сервис джобы. Ключ — секрет репозитория `OPENROUTER_API_KEY`.
Репортер `@e2e-dev/github` ведёт в PR один комментарий с итогом, токенами и
ценой. В CI кэш только читается, повтор упавшего теста — один. Отчёт, трейсы
и лог приложения лежат в артефакте `e2e-report`.

## Устройство

```
e2e.config.ts             раннер: приложение, модель, таймауты, репортеры
e2e/env.ts                переменные раннера
e2e/session.e2e.ts        вход нового человека → сессия "person"
e2e/person.ts             newPhone, signIn, ownPersonTest
e2e/<раздел>/*.e2e.ts     тесты раздела
e2e/chat/bro.ts           sendToBro — отправить и дождаться конца хода
.e2e/cache/               записанные шаги agent.act, коммитятся
```

- **Сессия `person`.** Это общий вошедший человек для тестов, которые только
  читают (`{ session: "person" }`). Тесты на ней идут параллельно, поэтому
  тест, который меняет общее (профиль, часовой пояс, сейф), входит своим
  человеком через `ownPersonTest`. Иначе он сломает соседей: так ловилось
  «Europe/Moscow» в кабинете, пока соседний тест менял пояс.
- **Каждый вход — новый номер** (`newPhone`). Поэтому повторы и прогоны не
  видят чужих данных, и CI не нужна чистка базы.
- **Теги.** `smoke` — без ходов Бро. `agent` — ходы самого Бро: медленные и
  платные, а их текст каждый раз новый.

## Как писать тест

1. Найдите имена на экране: роли, подписи, тексты кнопок. Посмотреть их
   можно в компонентах, в `--headed` или в `screen.txt` упавшего теста.
   Если у элемента нет доступного имени, добавьте в приложение `aria-label`
   или заголовок, а не CSS-селектор.
2. Точное действие делайте через `screen`, цель — через `agent.act`. После
   каждого `act` проверяйте исход через `expect`: без этой проверки шаг не
   запишется в кэш.
3. Ответы Бро проверяйте по факту (`toContainText("Париж")`) или через
   `agent.assert` по смыслу, но никогда по точной фразе. Сообщение Бро
   отправляйте через `sendToBro`. Один пузырь ещё не конец хода, а сообщение,
   отправленное посреди хода, перехватывает этот ход.
4. Роль `log` у ленты чата раннер не типизирует, поэтому вместо неё берите
   `chatLog(screen)`, то есть `main`.
5. Значения, которые модель не должна видеть, кладите в `secrets` в
   `e2e.config.ts` и передавайте через `secrets.get(…)` в `params`.
6. Прогоните тест локально, чтобы `agent.act` записался, и закоммитьте новые
   файлы `.e2e/cache/`. Без записи CI тоже пройдёт, но каждый раз будет
   платить за шаг.

Раннер ведёт свой навык для агентов: `.claude/skills/e2e` — ссылка на
`node_modules/e2e/skills/e2e`. Справку для установленной версии печатает
`pnpm exec e2e guide <тема>`: `writing-tests`, `agent`, `running`,
`debugging`.

## Набор растёт вместе с Бро

- Изменение страницы, формы, навигации или поведения в чате идёт в том же PR
  с тестом в `e2e/` (правило в `AGENTS.md`). Исправление бага — с тестом,
  который падал до исправления.
- Новый раздел приложения — это новый каталог `e2e/<раздел>/`. Новый маршрут
  добавьте в разогрев в `e2e/session.e2e.ts`: `next dev` компилирует маршрут
  при первом заходе, и на раннере CI это десятки секунд.
- Найденный дефект, который в этом PR не чинят, становится тестом со `skip` и
  причиной. Исправление снимает `skip`. Пропускать так тест, который раньше
  проходил, нельзя.
- Раз в несколько недель прогоняйте `pnpm exec e2e explore "<цель>"` или
  bug bash (`pnpm exec e2e guide bug-bash`). Найденное закрепляйте тестом.

## Известные дефекты

- `e2e/chat/first-contact.e2e.ts` пропущен. Если первое сообщение нового
  человека — вопрос без приветствия («Как называется столица Франции?»),
  deepseek-v4.1-flash тратит весь ход на знакомство (два-три пузыря) и не
  отвечает: так было в 3 из 4 прогонов 02.10. С «Привет!» в начале ответ
  приходил в 4 из 4. «Первый контакт» в
  `agent/instructions/content/role/interactive.md` требует сначала
  знакомство, потом дело.

## Обновление раннера

`e2e`, `@e2e-dev/web` и `@e2e-dev/github` до 1.0 меняют API между минорными
версиями, поэтому версии закреплены точно, как и `playwright`, которого
требует `@e2e-dev/web`. После обновления прогоните весь набор. Если версия
движка сменила минор, записи кэша перестанут совпадать: удалите их
(`pnpm exec e2e cache clear`) и запишите заново.
