# Bro

Personal iMessage concierge. **eve** runs the agent. **Convex** holds tenants, orders, and long-term memory (one store per person). **Photon Spectrum Pro** is the iMessage chat transport (shared pool, blue only — never SMS/RCS). **Inkbox** is mail-only: Bro mailbox, OTP, `[event:mail]`. **Supermemory** (optional, paid) adds automatic conversation memory.

Outbound replies are compiled to iMessage text: markdown is stripped, `**latin**` becomes Unicode math-bold (looks bold on iPhone), Russian field labels get a `▸` mark, long numbered dumps become one bubble per item. Photon Pro has no native iOS 18 cards or groups.

Telegram is a **second channel on the same tenant** (same phone, Bro mailbox, Gmail/Calendar, eve session). The human texts «телеграм» in iMessage, opens `t.me/<bot>?start=bind_…`, and later replies follow `lastChannel`. Markdown becomes Telegram HTML (`**привет**` is real bold; `++u++`, `||spoiler||`, `>` / `>!` quotes, `!![alt](url)` hidden media). Structured cards (`#` headings, lists, `:::rich`) go out as `sendRichMessage` and fall back to classic HTML if the method is missing. Optional `:::buttons` inline keyboards, photos, voice STT, and reactions. Outbound photos are real attachments on both channels: `send_photo` uploads a saved file or a public https image, and `![alt](https://…)` in a reply becomes `sendPhoto` on Telegram and Photon attachments on iMessage. Bro keeps the person's files in Convex storage (`files_*`); convert/OCR/PDF work runs in a short-lived sandbox (`sandbox_run`) the person never sees. Check: `npm run photo:check`, `npm run files:check`, `npm run sandbox-run:check`. Unbound Telegram users are told to start from iMessage — no second identity. Env: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `TELEGRAM_WEBHOOK_SECRET`. `npm run telegram:webhooks` once. Check: `npm run telegram:check`. Inbound photos reach the model as image parts (`deepseek/deepseek-v4.1-flash` has vision): bytes are downloaded up to 3 MB and sent as a plain `data:` base64 string so the picture survives the signed URL — never a `Uint8Array`/`URL` object, because eve serialises the turn input into memory-tool closures as JSON and those types break that; larger or failed downloads become the plain URL string instead. The URL also stays in the text for `browser_task`. Other attachments stay URLs. Check: `npm run imessage:check`, `npm run image:check`.

Voice notes: inbound audio is transcribed via OpenRouter STT (`/audio/transcriptions`) before the model sees it (`[voice] …`). Default `qwen/qwen3-asr-flash-2026-02-10` (best digit/time/brand accuracy on Russian in our bake-off, ~1.5 s, ~$0.001 per 30 s), fallback `openai/gpt-4o-transcribe`, language hint `ru`. iPhone CAF Opus is remuxed to Ogg in TypeScript — no provider accepts CAF and there is no ffmpeg on Vercel. If transcription fails and there is no other text, Bro sends a short Russian retry line and skips the agent. Override with `BRO_STT_MODEL` / `BRO_STT_FALLBACK_MODEL` / `BRO_STT_LANGUAGE`. Check: `npm run voice:check`.

## Needs

- Node 24 (`nvm use`)
- Inkbox API key, OpenRouter (`deepseek/deepseek-v4.1-flash`, override with `BRO_MODEL` / `BRO_MODEL_CONTEXT_TOKENS`) or Vercel AI Gateway
- TinyFish API key (optional; `web_search` / `web_fetch` for public facts). Without it those tools say they are unset. Interactive shops stay on Browser Use.

## Run

```bash
cp .env.example .env.local
# fill INKBOX_*, OPENROUTER_API_KEY (or AI_GATEWAY_API_KEY), ALLOWED_SENDERS
npm run memory:check
npm run provision:inkbox    # once — mail-only identity
npm run webhooks            # once: Inkbox mail signing key
npm run photon:webhooks     # once: Photon inbound URL + SPECTRUM_WEBHOOK_SECRET
npm run dev:local           # eve :2000
```

Production: Convex cloud + `eve deploy` on Vercel — `npm run deploy` does both in order (`CONVEX_DEPLOY_KEY`, `VERCEL_TOKEN`, optional `VERCEL_PROJECT` / `VERCEL_TEAM`; the script trims stray whitespace from the keys because both CLIs reject a token with a trailing newline). The static landing/cabinet site (`brobro`) deploys from git on push to `main`. Photon webhook is `https://<host>/webhooks/photon`. Inkbox mail webhook stays `/webhooks/mail`.

`npm run dev` is TUI-only (no public URL).

## Checks

`npm run check` runs the whole battery — `types:check` plus every other `*:check` script — in parallel, and prints the full output of whatever failed. They are pure-logic assertions over the policy modules: no network, no secrets, no deployment, ~10 s for all of them. `--only=onboard,silent` narrows to a few, `--skip=types` drops one, `--list` prints the selection, `--jobs=N` sets the concurrency. The Composio checks are excluded because they need a real `.env.local` and a live API key — run `npm run composio:check` by hand. GitHub Actions (`.github/workflows/checks.yml`) runs `npm run check` on every push and pull request, so a broken reply table or a dropped outcome branch is red before it reaches a real conversation.

## Cloud testing

Testing a change used to mean deploying it, picking up an iPhone and texting Bro. `npm run e2e -- --base=https://<eve host>` does that conversation in the cloud instead: it walks a deployed Bro through `scripts/lib/scenarios.ts` and checks what comes back.

A tenant whose phone sits in the fictional `+1555555` range (`convex/lib/testTenantPolicy.ts`) is a test tenant, and its outbound is recorded into the `testTranscript` table instead of sent. There are two sinks, because there are two ways Bro speaks. `deliverHuman` covers everything the agent says — a turn, a wakeup, browser follow-through, `profile_setup` — and records the channel it would have gone out on. `sendPhotonText` covers the rest: the welcome letter, the Telegram invite, the quota paywall and the SMS refusal are written straight to the transport with a conversation id and no tenant in hand, which is why a test conversation id (`test-space-<phone>`) has to name its tenant. Recording only at the `deliverHuman` layer left onboarding invisible — the send failed against a number no carrier assigns, the caller's `try/catch` swallowed it, and a first-contact scenario saw silence. Message counting and browser quota skip test tenants, or a nightly run would paywall itself halfway through.

The range is a constant rather than an env var on purpose: an env-configurable one is a single typo (`+7`) away from silencing every real person on the deployment, and it would fail silently. Every recorder function refuses a phone outside the range on the Convex side too, so the worst a misdirected run can do is read and clear rows for a number no carrier assigns.

There is no test-only inbound route. A turn is a synthetic Photon payload signed with `signSpectrumWebhook` — the exact inverse of `photonWebhookOk`, kept in the same file so the two cannot drift — posted to the real `/webhooks/photon`, so a run exercises signature checking, bind, the quota gate, the fast-ack lane and the actual turn rather than a copy that stops matching the day the real path changes. Only two routes are test-only, and both are read-or-reset: `POST /internal/test/transcript` reads back what Bro said, `POST /internal/test/reset` puts one tenant back to a clean slate (transcript, memories, wakeups, jobs, orders, browser state, the eve session, and `photonConversationId` — that last one because `bindPhotonInbound` decides `firstBind` from exactly it, so without it the onboarding scenario would pass once and never again).

A turn ends on quiet, not on the first bubble: Bro legitimately sends several for one message. The fast-ack status line is tagged `note: "fast-ack"` in the transcript, so a scenario asserting «он ответил» is not satisfied by the ack alone when the turn itself died. Scenarios anchor on constants the product already owns — a line of `welcomeBubbles()`, not a sentence retyped in the test — and assert loosely on anything the model phrases freely.

`npm run e2e:check` is the harness testing itself, with no secrets and no network: it stands up a fake Bro on localhost that verifies the signature for real, then checks that the runner passes on correct replies and fails on a repeated welcome letter, on silence, on a fast-ack-only turn, on a rejected secret and on an unknown scenario name. A suite that cannot fail is not evidence of anything, and that is invisible from a green run against a real deployment. Check: `npm run test-tenant:check`, `npm run e2e:check`.

`.github/workflows/e2e.yml` runs the suite nightly, on pull requests, and on demand, and opens (or comments on) an issue when a nightly run goes red. It needs three repository secrets — `BRO_E2E_BASE`, `BRO_INTERNAL_SECRET`, `SPECTRUM_WEBHOOK_SECRET` — and skips with a note until they are set, so an unconfigured repo does not carry a permanently red check. Point `BRO_E2E_BASE` at a staging deployment rather than production: nothing a run does can reach a real person, but each turn is a real model call and a real browser job, and those are billed wherever they run.

Flags: `--only=onboard-letter,memory` picks scenarios, `--jobs=N` sets how many run at once (each has its own tenant, so they are safe in parallel), `--settle=ms` is how long a turn must stay quiet before it counts as finished, and `--turn-timeout=ms` is the ceiling per turn.

Browser errands are the slowest and least deterministic thing to test by hand, so `scripts/fake-browser-use.ts` stands in for Browser Use Cloud v4: `node --experimental-strip-types scripts/fake-browser-use.ts --port=8787`, then point the staging deployment at it with `BROWSER_USE_BASE_URL=https://<host>/api/v4` — on **both** eve and Convex, because follow-through polling runs on the Convex deployment and redirecting only one side would start a fake run and then poll the real API for a run id it has never heard of. The fake picks its ending from the errand the model wrote (a plain purchase completes with `ЗАКАЗ`/`СУММА`; one mentioning the bank parks on `НУЖНО: 3ds`; a broken site fails), and runs take `--run-ms` so the progress notes and the busy/queue branches still happen. It is a base URL rather than a «притворись» flag on purpose: a flag that leaked into production would silently make Bro act as if it had bought things, while a wrong base URL is a deliberate act visible in `convex env list`. The `buy` and `pay-3ds` scenarios skip unless `BRO_E2E_FAKE_BROWSER` is set on the runner. Check: `npm run fake-browser:check`, which drives the real Browser Use client against the fake and asserts the result parses into a `CloudOutcome`.

Memory is three eve slots, all keyed by the person's E.164. `memo` (always on) is curated facts in the Convex `memories` table: recalled every turn, maintained by the model via `memo__remember` / `memo__search` / `memo__forget`, deduped and capped at 400 lines per person. `recall` mounts only when `SUPERMEMORY_API_KEY` is set: [Supermemory](https://supermemory.ai) then captures completed turns automatically, recalls relevant context before each turn, and adds `recall__search` and friends — no extra setup. Without the key both Supermemory slots are disabled and nothing breaks. Check: `npm run memory:check`.

`archive` is the Instinct-style layer (also Supermemory-gated): a Convex cron POSTs `/internal/memory-sync` hourly per active tenant, the eve route copies fresh Gmail and upcoming Calendar items via Composio into one Supermemory container per person (`bro_archive_<E.164>`, upserts by `customId`), and the slot semantically searches that archive with the current request before every turn. Archived copies survive app disconnects — deletion is the explicit `archive__forget` tool. Check: `npm run archive:check`.

Push watchers (`watch_app`): Composio triggers POST Convex `/composio`, then one agent turn per event. Subscribe once with `npm run composio:webhook https://<deployment>.convex.site/composio`. Prices/websites still poll via `schedule_wakeup kind=watcher`. Check: `npm run watchers:check`.

Public facts use TinyFish Search + Fetch (`web_search`, `web_fetch`) — free, even at a $0 wallet; rate limits only (PAYG: 30 searches/min, 150 fetch URLs/min). Set `TINYFISH_API_KEY` (from [agent.tinyfish.ai/api-keys](https://agent.tinyfish.ai/api-keys)) on eve / Vercel. Interactive shops, bookings, and logins stay on `browser_task`. Check: `npm run tinyfish:check`.

Sandbox tools (`COMPOSIO_REMOTE_WORKBENCH`, `COMPOSIO_REMOTE_BASH_TOOL`) have no web access by policy; facts go through TinyFish, shops through `browser_task`. Check: `npm run sandbox:check`.

Landing CTA creates a mail-only Inkbox identity plus a Photon shared user, then opens Messages (`sms:` to the assigned +1).
`assets/config.js` holds the Convex HTTP site URL (`https://<deployment>.convex.site`).
Set `INKBOX_API_KEY`, `INKBOX_WEBHOOK_URL`, and the `SPECTRUM_*` keys on the Convex deployment. Also required on the Convex deployment (not just eve/Vercel): `BROWSERUSE_API_KEY` (or `BROWSER_USE_API_KEY`), `EVE_URL`, and `BRO_INTERNAL_SECRET` — `convex/browserFollow.ts`'s follow-through polling runs there and calls Browser Use Cloud and eve directly. Without `BROWSERUSE_API_KEY` set on Convex, every browser run reads status `unknown` for the full 20-minute poll budget before giving up, instead of reporting back quickly. `OPENROUTER_API_KEY` is also read on the Convex deployment, by the phrasing lane above, but it is optional — `scripts/deploy.sh` prints the `npx convex env set` command instead of failing, and an unset key just means the canned wording. `npm run deploy` (`scripts/deploy.sh`) checks the required ones before `convex deploy` and fails loudly if any are missing; pass `--skip-env-check` to bypass. Note that a key pasted into a hosted env can carry a newline mid-string and `fetch` rejects such a header outright, so both model lanes strip all whitespace from it rather than trimming the ends. The Browser Use key hit exactly this in a deployed session, so both browser clients (`agent/lib/browseruse.ts`, `convex/lib/browseruse.ts`) normalize it the same way and log a one-line warning when the stored value needed stripping — that warning means the secret itself is still wrapped and wants re-setting.
Cap is `BRO_IDENTITY_CAP` (default 100). One tenant per phone: `POST /access` refuses a number that already belongs to someone (memories, wakeups and the cabinet are keyed by phone), and identity creation is rate limited to `BRO_ACCESS_CREATES_PER_HOUR` (default 20) because the iOS user-agent gate is spoofable. Check: `npm run access:check`.

Billing is a one-shot YooKassa month. Set `YOOKASSA_SHOP_ID` / `YOOKASSA_SECRET_KEY` on the Convex deployment; webhook URL is `https://<deployment>.convex.site/yookassa`. Empty keys keep the free beta, with daily message and monthly browser-job limits.

The landing «Войти» button opens a cabinet. First access still goes through «Запросить доступ». Later logins send a one-time code to the bound iMessage thread. Cabinet reads (`GET /me`) take a session token, never a tenant id. Check: `npm run cabinet:check`.

Site logins (any site): Bro reads a matching vault login (`kind: login`) and types it in Browser Use via `secretBindings`. If the Cloud profile already has cookies for that site, Bro does not send another login link and does not start a Passport job (a run that reports `need:"password"` invalidates that cookie cache — it never meant a real login). The profile name is a SHA-256 hash of the phone number, never the raw number; `BROWSER_USE_PROFILE_ID` only applies to the one tenant named by `BROWSER_USE_PROFILE_PHONE`, everyone else gets their own hashed profile. Taxi / shop errands open the real site over CDP after `browser.ready` (v4 has no startUrl) so a dead Cloud LLM cannot leave `about:blank`. If neither vault nor cookies exist, Bro opens the site login page over CDP and then texts a live-view link — they sign in themselves, cookies stay on the Cloud profile. The link is not sent while the preview is blank. Bro never asks for a site password in iMessage and never uses chat as a fallback. People add or edit those logins on brobro.tech (`/vault.html`). Check: `npm run profile:check`, `npm run browser:check`.

Every run ends on a mandatory labelled block (`СДЕЛАНО`/`ЗАКАЗ`/`СУММА`/`КОГДА`/`ВАРИАНТЫ`/`НУЖНО`/`ДЕТАЛИ`) that `parseCloudOutcome` (`convex/lib/browserOutcomePolicy.ts`) turns into a typed `CloudOutcome` — every downstream decision (inject, wakeup phase, the human-facing line) reads `needs` off that, with a free-text regex fallback only for a run that predates the label. One browser job per tenant: a second errand while one is active returns `busy` and queues onto `browserNextTask`, which the `done` wakeup starts on its own; `reset:true` or starting a genuinely new errand cancels the prior run (`POST /runs/{id}/cancel`) and stops its browser (`PATCH /browsers/{id}`) so a fresh session opens per errand instead of a stale one being reused up to Browser Use's 4-hour cap. `/internal/wakeup`'s `browser_poll` kind now carries the resolved phase (`done`/`need`/`failed`/`giveup`) plus the scrubbed result, `need`, and `liveUrl`, so the model reports without calling `browser_task` again; delivery is deduped durably in Convex (`wakeupDeliveries` / `claimDurableWakeupDelivery`), not an in-memory `Map`. A run parked on `browserNeed` (code/3DS/captcha/password/missing data) for more than 40 minutes is given up on by `sweepWaiting` (`convex/browserFollow.ts`), which stops polling and notifies once instead of forever. Check: `npm run outcome:check`, `npm run browser:check`, `npm run browser-task:check`.

`pollRun` closes two smaller silence gaps around that final block via `convex/lib/browserProgressPolicy.ts`. While the run is still in flight it sends at most one short progress note per key — one once a real page loads, one once the run has gone on with nothing sent yet, one later still — each delivered once per run through `/internal/deliver` and tracked on `tenant.browserProgressSent` so a retried poll never repeats one. A note never reads a hostname out loud and never echoes the errand text back at the person who just typed it: `humanSitePhrase` names the place the way people do («в яндекс такси», «на вб», «в озоне») and an unmappable host simply drops the place. The wording itself is written by a model, not chosen from a list: a tiny phrasing lane (`convex/lib/broPhrasing.ts`, `internal.phrasing.phraseLine`) takes the already-parsed facts and writes one short line in Bro's register inside a hard budget (1000 ms for a note, 1200 ms for the done report; measured median ~770 ms). The four canned wordings per key stay as the fallback, still picked by FNV-1a over the `runId` so a retried poll cannot rephrase itself. The gate falls back on a budget miss, a non-200, a truncated completion, too many lines, a URL, a field label, an emoji, a «Бро» opener, anything `scrubSecrets` touches, any digit the outcome did not carry, a done line that lost the order number or the sum, and a `long` note that lost «отмени». The model only ever sees parsed fields — the raw run result never leaves `pollRun`, and the action's `facts` validator is a closed object. `OPENROUTER_API_KEY` on the Convex deployment turns the lane on; with no key there is no fetch, no hop and no log, and every line reads exactly as it did before. `BRO_PHRASING=off` kills it, `BRO_PHRASE_MODEL` / `BRO_PHRASE_BUDGET_MS` / `BRO_PHRASE_PROGRESS_BUDGET_MS` tune it. Check: `npm run phrasing:check`. A run the human has stopped hearing about (`startFollowThrough`'s cancel-then-start can replace a workflow's next poll before it runs) but that finishes anyway still gets one late notice — `lateResultLine` fires only for a labelled, fully-resolved `done` — deduped durably under `browser_late:<runId>` (`wakeups.takeDelivery`), the same key `/internal/wakeup`'s own stale-run branch in `agent/channels/imessage.ts` uses so only one of the two paths ever speaks for a given run. And a `turn.failed` `browser_poll` wakeup — the model's turn threw instead of ending on empty text — now still delivers the canned outcome line (`fallbackForFailed`, `agent/lib/silent-turn.ts`) instead of leaving the human on read. Check: `npm run progress:check`.

The vault holds per-tenant logins, cards, addresses, and contacts. AES-256-GCM keys are derived from `BRO_VAULT_KEY` (set on the Convex deployment; `openssl rand -base64 32`). Losing or rotating it makes existing items undecryptable. The model only ever receives opaque handles; secrets are injected into the page over CDP or Browser Use `secretBindings` and masked in screenshots. The human types them at `/vault.html` behind the cabinet login. Vault links use `BRO_CABINET_BASE`. `profile_setup` takes an `errand` (the original ask), stored as `browserNextTask` so the errand resumes itself once the login lands, and never charges a browser-job quota on its own — `browser_task` charges once the errand itself starts running, keyed so a login-then-errand continuation or a pay-forced restart cannot double-charge. The `worker` subagent needs `KERNEL_API_KEY` (Kernel cloud browsers); without it `worker` fails with a clear error and `browser_task` keeps working. Worker passes `long_lived: true` to `manage_browsers create` for any login/checkout/OTP assignment (Kernel cannot extend a running session's timeout later) and reports back `needs`/`liveViewUrl` on `final_output` — it never resolves a 3-D Secure/OTP/captcha that appeared in the `browser_task` tab, only its own Kernel session's own challenges. A separate 30-minute Convex cron (`browsersGc.sweep`) deletes orphaned Kernel browsers and stale `browserSessions` rows the worker itself left open. Proxy: `BRO_KERNEL_PROXY_COUNTRY` (default `ru`, `none` disables) or `BRO_KERNEL_PROXY_ID`; `BRO_KERNEL_REGION` moves the browser VM off Kernel's `us-east` default. One `worker` assignment costs one browser job however many browsers it opens. Check: `npm run vault:check`, `npm run worker:check`, `npm run types:check`.

Bro can also pay with the vault card inside a `browser_task` run itself, via Browser Use Cloud `secretBindings`: the server types the card into the focused field on the allowed hosts, the model never sees the value, and the bindings die with the run. The bound set is no longer just the hostnames the model named — a card form almost never lives on the merchant host (Yandex renders it on `pay.`/`trust.yandex.ru`, and plenty of shops hand checkout to a processor), so `expandPayHosts` widens each host to its registrable domain, adds a small curated cross-TLD table and the common Russian card-form hosts, and caps the result at the API's 10 so truncation drops the lowest-priority tail rather than the widening. Bank entries name the acquiring subdomain only, never the bare bank domain — a card must never be typeable on an online-banking login page — and `expandLoginHosts` does the same for a saved password minus the processors, which is what lets a Yandex login be typed on `passport.yandex.ru`. «Привяжи карту» is its own errand shape (`isAttachCardErrand`): it binds the vault card with no purchase attached, forces a fresh run because bindings are run-scoped, survives the bank's 3-D Secure round trip with the card still bound, and records no order — the ~1 ₽ hold is not a purchase. A buy request or a «купи когда…» watcher pays without a second confirmation of shop/item/qty/total; `maxRub` is only a named budget. 3-D Secure, SMS codes, and bank-app confirmation still go to the human via live URL, resolved from the same `НУЖНО` outcome rather than free-text guessing. The order is recorded once on any completion path — a fresh run, a poll, a mid-run inject, or a run that finishes in the background — because `browserPaying`/`browserPayHosts` persist on the tenant instead of living only in the synchronous call that started the run. The background path matters now that `deliverDoneNow` reports a clean success without a model turn: `orders` used to be written only from inside the `browser_task` tool, so a purchase that landed in the background never reached «где мой заказ». Both paths now call the one gate and parser (`convex/lib/orderRecordPolicy.ts` over `convex/lib/orderPolicy.ts`, which is why those parsers live under `convex/` — Convex bundles its own code and never imports from `agent/`), and `api.orders.record` is an upsert on `(tenantId, merchantOrderId)`, so overlapping writes leave one row. Convex records before delivering, so a failed send cannot lose the row. A run replaced by a newer errand is skipped rather than attributed to the wrong one. Check: `npm run pay:check`, `npm run purchase:check`.

Bro's Inkbox mailbox is live: inbound `POST /webhooks/mail`, outbound `bro_mail`. `bro_mail` action=inbox lists recent inbound. When a worker needs an OTP (bank / WB / clinic), Bro looks in that inbox and the Instinct archive first (`otp` subagent or `otp_lookup`) and only asks in the iMessage thread if the letter is missing. Inbound Bro mail is also copied into the archive when Supermemory is on. Check: `npm run otp:check`.
Long work parks as Convex `jobs` (`npm run jobs:check`). Re-run `npm run webhooks` to subscribe mail.

Convex `returns:` validators reject documents with unknown fields, so every full-document validator (`tenantDoc`, `jobDoc`, …) is `doc(schema, "<table>")` from convex-helpers, never a hand-copied field list. Adding a column to `convex/schema.ts` is enough. Check: `npm run schema:check` (fails on any `v.object({ _id: v.id(…) })` literal in `convex/`). Postmortem 2026-09-05: a hand-copied `tenantDoc` without `archiveSyncedAt` made every tenant read throw once the hourly archive sync wrote that column, and Bro went silent.

Latency (2026-09-14): DeepSeek V4.1 Flash thinks at effort `high` by default and even `low` spends ~1,600 hidden tokens before the first visible character — most of the wait for the first bubble. Chat turns run with `reasoning: { enabled: false }` (`BRO_REASONING_EFFORT=low|high|max` brings thinking back). OpenRouter picks the lowest-latency host (`provider.sort=latency`, soft p90 2.5 s cutoff); a pinned `provider.order` is off by default because it disables sticky routing and the upstream prompt cache — `BRO_OPENROUTER_PROVIDER_ORDER` pins one again. One Spectrum app per instance serves every Photon send (a boot is two Photon HTTP calls plus a TLS gRPC handshake; `BRO_PHOTON_KEEPALIVE=0` reverts). The Photon webhook shows «печатает…» before the first Convex hop and re-arms it around tools. `POST /internal/warm` (Convex cron every 4 min) keeps the Vercel instance, the Photon client and OpenRouter warm. Eve runs the turn in a separate queue-triggered Vercel function (`.well-known/workflow/v1/flow`), so in-memory prefetches made in the webhook do not reach the model call — only server-side effects (the OpenRouter prefix warm, the Photon typing indicator) cross that boundary, and the Instinct recall budget is 900 ms because it gates the first token there. Every turn log line carries `sinceInboundMs` (stamped `inboundAt` on the auth attributes) — `turn started`, `turn deliver …`, `turn first bubble delivered`. Fast-ack lane: since the real turn always pays the queue hop + cold start + memory recall + model TTFT before its own first bubble, each webhook also fires a tiny no-reasoning OpenRouter call (`agent/lib/fast-ack.ts`) that turns the human's message into a freshly composed 2-6 word «взялся» line and sends it itself within a `BRO_FAST_ACK_BUDGET_MS` budget (default 700 ms) — the real turn is enqueued right after, at most that budget later, and runs unchanged. If the tiny call misses the budget it is aborted and nothing is sent; a stamped line whose Photon/Telegram send failed is logged as `fast ack deliver failed`. It runs at `temperature: 0.9` on purpose — wording collapses onto a single opener at 0.2, which is how «ищу» became the only thing Bro ever said — and its prompt carries at most a few examples, marked «не копируй», because a long roster of beats is something a tiny model reproduces verbatim instead of learning a register from — and `sanitizeFastAck` (≤6 words, ≤60 chars, no URL, no field label, no digit dump, never opening with «бро») throws away anything the wider sampling spoils. The result is stamped on the turn's `attributes` (the only thing that crosses into eve's separate workflow function), which steers the model not to repeat it and lets delivery dedupe a repeated looking line without it counting toward the empty-turn fallback. `BRO_FAST_ACK=0` disables the lane; `BRO_FAST_ACK_MODEL` picks a different model for it. Check: `npm run latency:check`, `npm run model:check`, `npm run photon:check`, `npm run fast-ack:check`. Browser-specific behavioral coverage lives in its own checks rather than here: `npm run outcome:check` (НУЖНО parsing), `npm run glue:check` (v4 live-URL/CDP/wakeup-claim glue), `npm run browser-task:check` (busy/reset/pay/inject settle paths), `npm run instructions:check` (root prompt stays free of jargon and keeps the canonical reply table).

Model calls always carry `max_tokens` (default 8192, `BRO_MAX_OUTPUT_TOKENS`): OpenRouter reserves the requested output length against the account balance before running, and without a cap it reserves the model's full 131k, so every turn fails with 402 as soon as credits dip. Postmortem 2026-09-06: `.harness/goals/openrouter-402-rca`. Check: `npm run model:check`.

A session that received a photo before #25 keeps `Uint8Array` parts in its eve history, and every memory-tool closure fails on each later turn. One-off cure: `POST /internal/session-clear` with `{ secret: BRO_INTERNAL_SECRET, conversationId }` (drops model history; Convex and Supermemory memory stay).

A human turn never ends in silence. Every `from().send` is stamped `origin: human | wakeup`; when a human-origin turn fails (`turn.failed`) or the model ends it with no text (tool errors, provider hiccup), the channel sends one short «что-то сломалось» line itself. Background wakeups may still end empty. Check: `npm run silent:check`.
