# Goal: Browser 3.0 — цельная автономная браузерная часть

Дата: 2026-09-15 (ночной прогон). Lead: Claude (планирует, ревьюит, коммитит).
Код пишут sonnet-субагенты по брифам из `briefs/`. Ветка `claude/adoring-dirac-hsvhfw`.

## Зачем

Bro должен выполнять поручения в облачном браузере **сам**: открыть сайт,
войти (сейф / куки / live-view только на OTP), заплатить картой из сейфа,
довести дело до конца и **написать первым**. Человек должен офигевать от
автономности. Сейчас цепочка «старт → доводка → код/пуш → live-view →
оплата → результат → заказ» рвётся на швах. Семь аудитов
(`/tmp/.../scratchpad/audits/A1..A7`, копии в `audits/` этой папки)
нашли ~50 дыр. Самые больные:

| # | Дыра | Откуда |

## Что строим (дизайн, утверждён Lead)

### 1. Протокол блокера (structured outcome) — сквозной
Cloud-агент заканчивает **обязательным блоком**:
```
СДЕЛАНО: <фраза>
ЗАКАЗ: <номер|нет>
СУММА: <₽|нет>
КОГДА: <дата/время/ETA|нет>
ВАРИАНТЫ: <до 5 «название — цена»|нет>
НУЖНО: none|sms_code|email_code|push|3ds|captcha|password|address|payment|info
```
Чистый парсер `parseCloudOutcome(result)` в `convex/lib/browserOutcomePolicy.ts`
(fallback на старые regex, если меток нет). Итог хранится на тенанте:
`browserNeed`, `browserNeedSince`. Все решения (инжект, wakeup-фазы,
подсказки модели, live-view) опираются на `browserNeed`, а не на угадывание.

### 2. Wakeup несёт результат
`wakeupAgent` шлёт в eve `phase: done|need|failed|giveup`, `result` (скраб),
`need`, `liveUrl`, `nextTask`. Роут `/internal/wakeup` строит точный промпт:
модель **пишет человеку без вызова тула** (готово / нужно от тебя / не вышло),
`browser_task` в wakeup-ходе только для инжекта или запуска `nextTask`.
Дедуп доставки — durable в Convex (`wakeupDeliveries`), не Map.
`email_code` → модель сначала `otp_lookup`, потом инжект — человека не трогаем.

### 3. Жизненный цикл run/session
`cancelRun`, `stopBrowser`. Новая сессия на каждое новое поручение; старый
run отменяется на `reset`, при старте нового поручения, на give-up.
Give-up ставит статус `stalled` (terminal для policy). Поллинг
10/15/20/30/45/60 с, затем 90 с, до 20 мин. Второе поручение при активном
джобе → `busy`: пишем «сначала закончу X, потом Y», кладём в
`browserNextTask`, wakeup после done сам его запускает.

### 4. Оплата, вход, заказы
`browserPaying`/`browserPayHosts` на тенанте → заказ записывается на любом
пути. `errandStartUrl` участвует в поиске логина в сейфе. `needsProfileSync`
не выдаётся, если логин из сейфа уже привязан к этому run. `profile_setup`:
guard на повтор (poll того же входа), без списания квоты, `errand` параметр
→ `browserNextTask`. Куки-кеш сбрасывается при `need=password`.
`BROWSER_USE_PROFILE_ID` действует только для `BROWSER_USE_PROFILE_PHONE`;
имя профиля — hash телефона. Результат Cloud скрабится от PAN/паролей.

### 5. Инжект
Новый kind `confirm` («подтвердил», «готово», «вошёл», «оплатил», «одобрил»)
— очередь в сессию даже после terminal-статуса. Liveness: таймер только
как верхняя граница при отсутствии явного «browser not listed». Голые цифры
— код только при `browserNeed ∈ {sms_code,email_code}` или ключевом слове.
Два числа → предпочесть то, что рядом с «код». CDP: без escape-hatch на
единственное поле. Честный hint при упавшей очереди. Fast-ack молчит на
код/подтверждение.

### 6. worker / otp
Редакция результата Playwright + статический guard на чтение секретов;
Kernel-таймаут 45 мин для входа/оплаты; `liveViewUrl` в выходе worker;
инструкция «3DS в Cloud-вкладке → только live-view Cloud, никогда worker»;
OTP-подбор с учётом hint отправителя.

### 7. Промпты
Новый скаффолд (≤25 строк, протокол блокера, баннеры/город/двойная
корзина/проверка номера заказа). Инструкции: одна каноническая таблица
«результат тула → что сказать», без жаргона. Один источник «ищу»-пузыря.

## Ограничения
- Ponytail: минимум кода, без новых зависимостей, чистые policy-функции + check-скрипты.
- Не трогать `convex/_generated/`, `vendor/`, формат iMessage-текста.
- Секреты только в env; ключей вендоров у агентов нет — всё проверяется структурно + моками.
- Каждый пакет: `npm run types:check`, затронутые `*:check`, `npx eve build` (Node 24 в `$SCRATCH/node24/bin`).
- Ревью Lead перед коммитом каждого пакета.
